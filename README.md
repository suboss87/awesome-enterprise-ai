# Awesome Enterprise AI

### Enterprise AI agents with measured results. Each solves one acute back-office problem, decides in code, and reports a live run against a non-AI baseline.

[The agents](#the-agents) · [Run one in two minutes](#run-one-in-two-minutes) · [How they are built](docs/ARCHITECTURE.md) · [How they are measured](docs/EVALUATION.md)

</div>

Most enterprise AI pilots never reach production. The ones that do share a shape: a narrow back-office workflow, a hard baseline, a measured result and a human approval gate. This collection is built that way: five agents today, ten planned, each small enough to read in an afternoon and built the way I would build them for a bank or an insurer.

Each agent uses a model for what models are good at: reading messy documents, noticing what a regex cannot, drafting. Plain code owns the decision: tolerances, matching, ranking, the route. Nothing is executed without a person. Every run leaves a trace with tool calls, tokens and cost.

## Evidence first

Every row below comes from a committed `evals/REPORT.md` produced by one live run on labeled synthetic cases, with a
rules-only baseline on the same cases. Synthetic means fictional, generated by a seeded script, labeled before any
model call. It does not establish production accuracy; it shows the model's contribution over rules alone and which failure modes stayed at zero on these cases.

| Agent | The model reads and drafts | Code decides | A person approves | Evidence (claude-opus-5-5, 2026-10-30) | Primary metric: agent vs baseline | Must-be-zero safety metric | Cost per case |
|---|---|---|---|---|---:|---:|---:|
| [AP Exception](projects/ap-exception-agent/) | Invoice in any layout, covering email, bank details, embedded instructions | 3-way match, tolerances, duplicates, route | Vendor query, release for payment | Live run, 120 cases (gpt-5.5) | Route 100% vs 79.2% | Unsafe auto-approvals 0 vs 13 | USD 0.049 |
| [Support Resolution](projects/support-resolution-agent/) | Ticket intent, permitted policy sections, the reply | Eligibility, limits, tenant and role boundaries, the action | Refund, return, cancellation, the reply | Live run, 142 cases | Route 100% vs 83.1% | Permission leaks 0; unauthorised actions 0 | USD 0.085 |
| [Incident Investigation](projects/incident-investigation-agent/) | Alerts, logs, deploys, runbooks; hypotheses and the RCA draft | Timeline order, evidence binding, what counts as confirmed | Mitigation, RCA post | Live run, 132 cases | Root cause 100% vs 69.7% | Innocent component blamed 0 vs 24 | USD 0.240 |
| [Claims Intake](projects/claims-intake-agent/) | FNOL, police report, estimate, photo notes | Completeness per coverage, conflict arbitration by source authority, triage | Missing-information request, adjuster hand-off | Live run, 130 cases | Route 100% vs 87.7% | Marked ready when not 0 vs 16 | USD 0.075 |
| [Vulnerability Triage](projects/vulnerability-triage-agent/) | Advisory text, reachability hints; justifications and tickets | KEV, EPSS, reachability ranking; VEX status rules | VEX statement, fix tickets | Live run, 124 cases | VEX status 100% vs 80.6% | Affected finding cleared 0; demotable ranked first 0 vs 24 | USD 0.142 |

Baselines are the same rules without a model: regex templates, keyword macros, exact joins. Where the baseline is already
right, the table says so. Latency is 15 to 35 seconds per case at medium effort; details and per-category tables are in
each report. Defects the evals found, and the fixes, are in the [failure log](docs/FAILURE-LOG.md).

## The agents

| Agent | Acute problem | Source for the number |
|---|---|---|
| [AP Exception Agent](projects/ap-exception-agent/) | Invoices cost about USD 9.90 each to process and 20% raise an exception. | Ardent Partners, 2026 |

Every project folder has the same parts: `README.md`, `agent.py`, a rules module, `baseline.py`, `evals/` with 100 or
more labeled cases and the committed report, `GOVERNANCE.md`, `tests/`, `examples/`. The [project standard](CONTRIBUTING.md)
lists what each must contain and the [rubric](docs/RUBRIC.md) says what earns a place here.

## Run one in two minutes

Python 3.11 or newer. Standard library only.

```sh
git clone https://github.com/suboss87/awesome-enterprise-ai.git
cd awesome-enterprise-ai
python3 -m enterprise_ai run ap-exception-agent          # replays recorded model calls, no key needed
python3 -m enterprise_ai serve                           # http://127.0.0.1:8765, shows the tool-call trace
```

With a key, run live and measure:

```sh
export ANTHROPIC_API_KEY=...                             # or OPENAI_API_KEY
python3 -m enterprise_ai run ap-exception-agent --input your-invoice-case.json
python3 -m enterprise_ai eval ap-exception-agent          # 120 cases, agent vs baseline, writes evals/REPORT.md
```

## What you can inspect

- **The decision boundary.** `GOVERNANCE.md` in each project says what the agent does alone, what it proposes, and what it never does.
- **The evidence.** Every finding quotes the source verbatim. The runtime rejects a result whose quote is not in the document.
- **The trace.** Each run records every model call and tool call with OpenTelemetry GenAI attribute names, token usage and cost.
- **The baseline.** The report shows the agent and the rules-only alternative on the same cases, so the model's contribution is a number, not a claim.
