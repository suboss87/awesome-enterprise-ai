# Contributing

This collection holds a small number of deep agents. A new agent is welcome when it
solves one acute, recurring enterprise problem and ships with everything below.
An improvement to an existing agent is welcome when it changes a measured number
or closes a documented limit.

## The project standard

Every folder under `projects/` has the same parts. Reviewers check each one.

| Part | What it must contain |
|---|---|
| `README.md` (about 500 words) | The problem with a public number, what the agent does, an architecture sketch, the results table copied from `evals/REPORT.md`, three commands to run it, the decision boundary, limits. |
| `agent.py` | `SPEC`, a versioned `SYSTEM_PROMPT`, typed tools built from the input, the `finish` result schema, `validate(data)` for the input contract, `run(data, provider, trace)`. Reads are tools; writes are tools with `writes=True` and are never executed. Code, not the model, owns the final decision. |
| `baseline.py` | `run(data)` with the same output shape, no model. The honest non-AI alternative a team would otherwise build. |
| `evals/generate_cases.py` | Seeded generator. Categories enumerate the hard cases from practice. Labels are fixed before any model call. |
| `evals/cases.jsonl` | 100 or more cases: `{id, category, input, expected}`. |
| `evals/score.py` | `METRICS`, `PRIMARY`, `score(case, output)`. At least one `zero` metric for the unsafe outcome. |
| `evals/REPORT.md` | Generated by `python3 -m enterprise_ai eval <slug>`. Committed with the model, date, cost and failure table. |
| `GOVERNANCE.md` (about 500 words) | Decision rights (alone / propose / never), data classification and PII handling, threat model, audit fields, kill switch and rollback, owners, acceptance thresholds. |
| `tests/` | Contract tests, rule tests, boundary tests (write tool blocked, fabricated quote rejected, model cannot force the safe-looking route), baseline behaviour, example replay. |
| `examples/` | `input.json` and `replay.json` (recorded live completions) so CI and the workspace run offline. |

## Working rules

- Standard library only. No new dependencies.
- The model reads, extracts, classifies and drafts. Rules compute, match and decide.
- Every quoted piece of evidence must exist verbatim in a supplied source. The runtime enforces this.
- Record initial failures in the report. Never edit an expected label to make a run pass.
- Keep API keys in the environment. Never commit raw eval runs that contain business data.

## Checks before a pull request

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
for p in projects/*/; do python3 -m unittest "$p"tests/test_*.py; done
python3 -m enterprise_ai run <slug>            # example replay
python3 -m enterprise_ai eval <slug> --baseline-only
```

Live evals cost money and need a key. Run them when the prompt, tools or rules change, and commit the new report.
