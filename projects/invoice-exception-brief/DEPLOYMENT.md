# Pilot deployment

Run locally under an account already authorized to read the source exports. The utility has no identity provider, access-control layer, encryption service or retention job. Store input and generated briefs in an approved location with existing filesystem permissions, retention and backup controls; reports can contain sensitive supplier and transaction information.

Before a real pilot, map every schema field to an authoritative source and test representative exceptions with accounts payable and receiving. Prove complete snapshot export across filters and pagination. Distinguish physically received, accepted and rejected quantities. Confirm prior posted invoice lines include all applicable consumed quantities and exclude current invoice, cancelled items and unsupported credits/returns.

Set the evaluation time and evidence-age policy explicitly. Compare source timestamps with the actual extraction time and invoice posting state. This is a point-in-time review, not a transaction lock. Never use a successful exit as an ERP payment authorization.

Measure false clean results, missed exceptions, reviewer agreement and time to prepare the brief against existing processes. No savings or production reliability are inferred from the synthetic tests. Regulated deployment needs organization-specific security, financial-control and retention review; no compliance certification is claimed.
