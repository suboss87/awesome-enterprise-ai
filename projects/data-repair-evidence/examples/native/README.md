# Real synthetic GX fixture provenance

`failed-gx.json` and `repaired-gx.json` were produced by actual local GX **1.8.0** runs, not handcrafted validation JSON. `suite.json` is the same native suite used for both. The two independently authored dataframes are included. One initially missing `order_id` is repaired; native content fingerprints consequently differ. Times and IDs come from actual execution. Hashes, Python version and every installed development distribution are recorded in `provenance.json`.

GX is used only to generate the synthetic fixtures. It is not a workspace runtime
requirement. The reproducible environment pins GX 1.8.0 and excludes development
distributions newer than 2026-09-18.

Recreate in a disposable environment (requires uv and network access):

```sh
uv venv /tmp/gx-data-repair-fixtures --python python3
uv pip install --python /tmp/gx-data-repair-fixtures/bin/python --exclude-newer 2026-09-18T00:00:00Z great-expectations==1.8.0
/tmp/gx-data-repair-fixtures/bin/python projects/data-repair-evidence/tools/generate_gx_fixtures.py
```

Recreation changes native IDs, timestamps, hashes and provenance. Rebind the new raw artifact hashes in the operator mapping and regenerate the normalized example; never edit hashes to hide changed input. The sibling dbt manifest is a separately authored minimal graph fixture, not generated by dbt. Upstream GX's Apache-2.0 implementation is used only to generate these original synthetic artifacts; no upstream fixture or source was copied.

## Genuine empty-batch regression

`empty-baseline-gx.json` and `empty-gx.json` are an additional actual GX 1.8.0 pair generated in the same previously installed isolated environment, with no new installation. The first fails on a missing order ID; the second passes both expectations on zero rows. `empty-suite.json` is their native suite; GX assigns new IDs when loading the previous configuration into a new ephemeral context. Their original rows, byte hashes, runtime and dependency provenance are in `empty-*-rows.json`, `empty-rows.json`, and `empty-provenance.json`. Previous fail/pass fixtures and their provenance remain unchanged.

```sh
/tmp/gx-data-repair-fixtures/bin/python projects/data-repair-evidence/tools/generate_empty_fixture.py
```

The workflow rejects this vacuous passing retest as `unverified`. This generated pair is an additional regression, not a new enterprise dataset or retrospective live-model evaluation.
